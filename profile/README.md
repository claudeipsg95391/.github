<p>如果只记一句话：先数清楚你有几个账号必须长期挂在同一个出口上，再决定买几条独享线。剩下的都是细节。这篇把选型过程做成一张可以打印出来的清单，分三层——地址与线路、交付与运维、合同与退出，每层列出必须当场问清的项目，最后按账号规模给三种配置组合。适合正在做季度采购、需要给团队一个可复核决策依据的人。</p>

<h2>一、先数清楚"必须固定"的出口有几个</h2>
<p>不是所有账号都需要固定出口。日报浏览、临时查资料这类用法，出口漂移影响不大；需要长期登录、绑定订阅、对外代表一个身份的账号，才值得单独占一条线。先把账号分成这两类，数量会少很多。</p>
<p>分完之后再乘一个系数：每个必须固定的账号，预留 1 条主用加 0.2 条备用。备用不一定要单独买，可以是同一供应商的第二条线，也可以是一个月付的临时出口，作用是主用挂掉时不至于停摆。</p>
<h3>算清楚峰值并发</h3>
<p>并发不等于账号数。十个人轮班用一个账号，峰值并发可能只有 2；一个人挂三个自动化任务，峰值可能到 6。按任务实际同时发起的请求数估，比按人头估准。</p>

<h2>二、清单上半页：地址与线路</h2>
<p>这一层的目标是确认"买到的到底是什么"。同样是独享，可能是整段独享、单 IP 独享，也可能只是通道独占而出口仍与他人共享。问法要具体到地址层面，不要停在套餐名上。</p>
<h3>地址归属与网段纯度</h3>
<p>要问清地址的 ASN、注册主体、是否为运营商直接分配。同网段已售出多少条、这些地址是否曾被用于高频请求，能答上来的供应商通常对自己的池子有掌控力。可以要求提供一条样例地址自行查询。</p>
<h3>带宽与并发上限</h3>
<p>带宽是共享还是独享、单条限速多少、并发连接数有没有上限，这三项都会直接影响体验。常见的坑是标称 100M，实际按 10M 限速，晚高峰再打对折。</p>

<h2>三、清单下半页：交付与运维</h2>
<p>线路好但交付慢、出事找不到人，一样会拖垮业务。这一层看的是流程：开通要多久、能不能自助换地址、工单多久有人接、有没有状态页。</p>

<h3>开通时效与自助面板</h3>
<p>理想情况是下单后一小时内可用，面板上能看到每条线的流量、在线状态、最近一次变更记录。只能靠人工开通、面板什么都没有的，扩容时会很痛。</p>
<h3>工单与值班</h3>
<p>问三个问题：晚高峰抖动怎么处理、地址被要求验证能提供什么协助、换线时效承诺几小时。回答里带具体时限和流程的，说明有值班机制；只说"放心"的，基本靠运气。</p>

<h2>四、合同里必须出现的三行字</h2>
<p>口头承诺在纠纷里没有分量。合同或订单备注里至少要写明三条：续费后地址是否保留、非自愿更换的补偿方式、提前退出的结算规则。这三条决定了你后期能不能低成本调整。</p>
<h3>地址保留条款</h3>
<p>静态独享的核心价值就是地址不变。如果续费换套餐就换地址，那和动态池差别不大。条款要写到"同一地址在合约期内不因套餐变更而变更"这个粒度。</p>
<h3>退出与结算</h3>
<p>月付按天折算、年付按剩余月份折算还是概不退款，差别很大。团队账号规模还在变的时候，优先选可月付、可停可续的方案，别为了两成折扣把自己锁一年。</p>

<h2>五、清单之外的三条否决项</h2>
<p>有些问题一旦出现，其他条件再好也该放弃。第一条，拒绝提供任何样例地址做查询；第二条，计费单位含糊，说不清是按流量还是按端口；第三条，工单系统不存在，只能通过个人社交账号联系。</p>
<p>这三条背后是同一个逻辑：不可验证。价格可以谈、地区可以换，但不可验证意味着你永远无法确认自己买到了什么，出问题时也没有留痕可查。</p>
<p>价格方面，美国静态独享住宅单条月付大致几十到两百元，欧洲部分地区更高，专线级线路另计，具体以报价单为准，仅供参考。预算表里的区间只用来判断量级，不适合直接当报价锚点。</p>

<h2>常见问答</h2>
<h3>账号不多，能不能几个人共用一条线？</h3>
<p>答：可以，但要接受两件事：一是并发会互相挤占，二是出口相同意味着行为记录会混在一起，出问题时难以区分是谁触发的。人数控制在两三人、且操作时段错开，风险相对小。</p>
<h3>备用线一定要买吗？</h3>
<p>答：看停机成本。如果停一天只是少看几个页面，可以不买；如果停一天会影响交付或客户沟通，就值得准备。备用可以是一条便宜的月付线，也可以是临时按天开通。</p>
<h3>年付折扣多大才值得考虑？</h3>
<p>答：通常在两成上下，仅供参考。判断标准不是折扣力度，而是你对这家供应商的稳定性是否有连续三个月的实测数据。没有数据就锁年付，等于把调整权交出去。</p>
<h3>供应商说独享，怎么确认？</h3>
<p>答：看两点。一是让它在面板上显示这条地址的分配记录，二是自己用两个不同网络同时访问，观察是否出现同地址的其他会话。更稳妥的做法是要求合同写明地址独占。</p>
